# DairyVision AI UX Specification

## 1. Product Vision

DairyVision AI is a farmer-first digital assistant for Indian dairy farms. The product must feel simple, trustworthy, and fast even for first-time smartphone users.

The guiding principle is that the farmer should do the minimum possible work. The system should automatically calculate, infer, and present the rest using backend logic, the ML engine, and weather data.

This document is the blueprint for the frontend experience and should guide every screen, interaction, and workflow.

---

## 2. UX Goals

- Make dairy management feel effortless for rural and semi-urban farmers.
- Minimize typing and manual data entry.
- Support low-bandwidth and low-tech environments.
- Support Indian dairy contexts, including local breeds, regional names, and multiple languages.
- Present critical information clearly using simple language and large touch targets.
- Help farmers act quickly when animals need attention.

---

## 3. UX Principles

### 3.1 Farmer-first design

- The experience should be designed around the farmer’s daily routine, not around technical workflows.
- Every screen should help the farmer complete one useful task quickly.
- The most important information should be visible without deep navigation.

### 3.2 Mobile-first responsive design

- The primary experience is a smartphone-based workflow.
- Interfaces must work well on small screens first and then scale to tablets and desktops.
- Navigation should be thumb-friendly and simple.

### 3.3 Large touch-friendly buttons

- Buttons should be large, clearly labeled, and easy to tap.
- Primary actions such as Add Cow and Record Observation should be prominent.
- Avoid dense forms and tiny controls.

### 3.4 Simple language

- Use short, familiar words.
- Prefer plain language over technical terms.
- Where technical terms are necessary, provide simple explanations.

### 3.5 Minimal typing

- Farmers should not be required to type long text whenever possible.
- Use chips, pickers, dropdowns, toggles, and prefilled values.
- Use voice or image-based inputs in the future, but not required in the first release.

### 3.6 Maximum automation

- Weather, THI, age, lactation stage, health score, risk score, milk predictions, and recommendations should be calculated automatically.
- The farmer should only enter values that are truly necessary for the current task.

### 3.7 Step-by-step workflows

- Complex tasks should be broken into short, guided steps.
- The app should avoid overwhelming the user with too many choices at once.
- Each step should have one clear purpose.

### 3.8 Multi-language ready

- Labels, buttons, and messages should be easy to translate.
- The interface should support local languages in future iterations.
- Breed aliases must also be local-language capable.

### 3.9 Accessible for first-time smartphone users

- Use simple icons with text labels.
- Keep navigation predictable.
- Avoid hidden gestures or complex interactions.
- Ensure contrast, readable font sizes, and clear states.

## 4. Automatic vs Manual Data

| Data Type            | Source    | Farmer Action                                |
| -------------------- | --------- | -------------------------------------------- |
| Cow registration     | Manual    | Farmer enters essential identity details     |
| Daily milk           | Manual    | Farmer enters milk produced                  |
| Feed quantity        | Manual    | Farmer enters today's feed amount            |
| Symptoms             | Manual    | Farmer selects symptoms using chips/buttons  |
| Notes                | Manual    | Farmer optionally adds short notes           |
| Weather              | Automatic | Fetched by weather API                       |
| THI                  | Automatic | Calculated from weather and farm context     |
| Heat stress level    | Automatic | Calculated from THI and environment          |
| Age                  | Automatic | Derived from birth date                      |
| Lactation stage      | Automatic | Derived from calving and observation history |
| Health score         | Automatic | Calculated by backend/ML engine              |
| Risk score           | Automatic | Calculated by backend/ML engine              |
| Milk prediction      | Automatic | Generated by ML engine                       |
| Digital Twin updates | Automatic | Updated after each observation               |
| Recommendations      | Automatic | Generated from rules and ML outputs          |

## 5. Core Application Flow

The user journey should be simple and linear:

Login
↓
Dashboard
↓
Farm
↓
Herd
↓
Cow Profile
↓
Daily Observation
↓
Prediction
↓
Health Assessment
↓
Digital Twin

### Flow Summary

1. The farmer logs in.
2. The dashboard shows status, alerts, weather, and quick actions.
3. The farmer opens the farm and herd views.
4. The farmer selects or adds a cow.
5. The farmer records a quick daily observation.
6. The system automatically calculates prediction and health status.
7. The farmer views alerts, recommendations, and digital twin insights.

## 6. Screen Design Standard

Each screen should include the following sections where relevant:

### 6.1 Purpose

- Defines the reason for this screen.

### 6.2 Primary user

- Identifies the main audience for the screen.

### 6.3 Actions

- The main tasks the user can perform.

### 6.4 Widgets

- UI elements used to present information such as cards, stat tiles, charts, buttons, and lists.

### 6.5 Buttons

- Primary, secondary, and tertiary actions.

### 6.6 Navigation

- How the user moves through the app.

### 6.7 Validation

- What the interface should check before allowing submission.

### 6.8 Empty state

- What the user sees when there is no data yet.

### 6.9 Error state

- What the user sees if something fails.

### 6.10 Loading state

- What the user sees while data is being fetched or calculated.

## 7. Screen Specifications

### 7.1 Login Screen

#### Purpose

Allow the farmer to securely enter the app quickly.

#### Primary user

Farmer or farm manager.

#### Actions

- Enter phone/email and password
- Tap Login
- Tap Forgot Password
- Tap Register

#### Widgets

- App logo or icon
- Email/phone field
- Password field
- Login button
- Secondary links

#### Buttons

- Primary: Login
- Secondary: Register
- Tertiary: Forgot Password

#### Navigation

- Login goes to Dashboard.
- Register goes to Registration.

#### Validation

- Required fields must be present.
- Password must meet minimum rules if authentication is enabled.

#### Empty state

- Show helpful text like “Enter your details to continue.”

#### Error state

- Show friendly error: “Unable to sign in. Please try again.”

#### Loading state

- Show a spinner and disable the button while signing in.

## 8. Dashboard Design Specification

### 8.1 Layout

The dashboard should be a calm, simple home screen. It should prioritize the most important needs of the day:

- What is the weather?
- What needs attention today?
- How many cows are healthy?
- What should I do now?

### 8.2 Dashboard Modules

#### Today’s Weather

- Show current weather clearly.
- Display temperature, humidity, and heat stress level if available.
- The farmer should never enter weather manually.

#### Today’s Tasks

- Show short actionable items like:
  - Record observation for 3 cows
  - Review 2 alerts
  - Check milk trend

#### Total Cows

- Big number tile showing the total herd size.

#### Healthy Cows

- Show the count of cows with stable current status.

#### Attention Needed

- Show the count of cows that need closer monitoring.

#### Critical Alerts

- Show urgent issues that require immediate action.

#### Today’s Milk Production

- Show aggregate milk volume for the day.

#### Quick Actions

- Add Cow
- Record Observation
- View Alerts
- Reports
- Scan QR

#### Recent Activity

- Show recent updates such as observations and alerts.

#### Upcoming Vaccinations

- Future feature placeholder, shown as a lightweight section.

## 9. Daily Observation Workflow

### 9.1 Core goal

The daily observation experience should take less than 30 seconds per cow.

### 9.2 Inputs requested

The farmer should only be asked for:

- Milk produced
- Feed quantity
- Symptoms via chips/buttons
- Optional notes

### 9.3 Automatic fields

The app should automatically fill or calculate:

- Weather
- THI
- Heat stress level
- Age
- Lactation stage
- Health score
- Risk score
- Prediction update
- Digital Twin update
- Recommendations

### 9.4 Interaction pattern

- Start with a single cow.
- Present the form in a compact vertical layout.
- Make the input fields large and clearly separated.
- Use big buttons for symptoms.
- Keep the form short and action-focused.

## 12. Digital Twin Experience

The Digital Twin is a dynamic, automatically updated view of a cow’s state.

### 12.1 Behavior

- After each observation, the system updates the cow’s digital twin automatically.
- Changes should be reflected in the cow profile without farmer intervention.
- The digital twin should summarize the current condition in a simple and understandable way.

### 12.2 What it may include

- Current health status
- Recent trend summary
- Risk indication
- Suggested monitoring need

---

## 13. Weather Experience

Weather is a core part of the experience and should be fully automated.

### 13.1 Behavior

- The app should fetch weather automatically using Open-Meteo.
- The farmer should never manually enter weather data.
- Weather should be used to calculate THI and heat stress level automatically.

### 13.2 Display

- Show a simple weather card with today’s conditions.
- If the data is delayed or unavailable, show a fallback state with a clear message.

---

## 14. Breed Experience

### 14.1 Design principle

Breed selection should feel natural and simple for the farmer.

### 14.2 Required behavior

- Use BreedMaster as the canonical breed source.
- Use BreedAlias for searchable local and regional names.
- Use a searchable dropdown for breed selection.
- Support Indian breeds, crossbreeds, and regional names.
- Support multiple languages in the future.
- Never allow free-text breed entry by default.

### 14.3 Interaction pattern

- Show a searchable dropdown with common Indian breed names.
- If the farmer starts typing, the system suggests matching breeds.
- The app should allow selection from known values rather than requiring manual writing.

## 15. Design System Recommendations

### 15.1 Color palette

Use a calm, trustworthy, and agricultural-friendly palette.

Suggested colors:

- Primary green: used for actions, success, and healthy status
- Warm amber: used for warnings and attention-needed states
- Red: used for critical alerts and urgent need
- Blue: used for weather and informational states
- Neutral gray: used for backgrounds, borders, and secondary text

### 15.2 Typography

- Use a simple, modern sans-serif font.
- Prioritize readability on small screens.
- Use larger font sizes for labels and main content.

### 15.3 Icons

- Use clear, simple icons that are easy to recognize.
- Avoid overly decorative icons.
- Pair icons with text where necessary.

### 15.4 Spacing

- Use generous spacing between sections.
- Avoid cluttered layouts.
- Keep content grouped into short, readable blocks.

### 15.5 Cards

- Use cards for summaries, alerts, and actions.
- Keep cards visually simple and consistent.

### 15.6 Buttons

- Use large rounded buttons.
- Primary actions should be prominent and high contrast.
- Secondary actions should be less visually dominant.

### 15.7 Forms

- One column layout on mobile.
- Large form labels and simple error messages.
- Keep forms short and focused.

### 15.8 Tables

- Prefer cards or list views over dense tables on mobile.
- Use tables only where comparison is necessary.

### 15.9 Status badges

- Use badges for healthy, attention-needed, critical, and inactive states.
- Make them visually distinct and easy to understand.

### 15.10 Alert colors

- Green for healthy or normal
- Amber for attention needed
- Red for critical

---

## 16. Interaction and Messaging Guidelines

- Messages should be short, encouraging, and practical.
- Use positive and calm language.
- Avoid technical jargon.
- Use consistent button labels such as Save, Continue, View Details, and Record Observation.
- Show progress clearly when the farmer is moving through a workflow.

---

## 17. Accessibility and Inclusivity

- Use sufficient contrast between text and background.
- Keep tap targets large enough for finger interaction.
- Avoid over-reliance on color alone for status.
- Support icon plus text labels.
- Prepare for multilingual use and local-language content.

---

## 18. Implementation Guidance for the Frontend Team

This document should be used as the product blueprint for frontend implementation.

The frontend should prioritize:

- speed
- clarity
- low cognitive load
- simple navigation
- minimal typing
- large touch targets
- automation-first behavior

The frontend implementation should never require the farmer to manually enter weather, THI, health scores, recommendations, or digital twin updates.
